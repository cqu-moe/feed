# Modern Web Guidance 项目适配

## 触发与流程

- 修改网页结构、样式、交互、浏览器 API、可访问性或前端性能前，读取当前安装的 `modern-web-guidance` 技能，按单个能力执行 `search`，再 `retrieve` 匹配的具体指南和相关通用指南。命令及技能版本参数以当前 `SKILL.md` 为准。
- 全项目现代化审查使用 `legacy-scan`，逐项按 `keepWhen` / `dropWhen` 核实；它只覆盖约 20% 的指南，不能代表完整的前端审查。指定组件或功能的改动直接检索相应指南。
- 后端业务、基础设施和纯工具配置沿用原有工程流程；扫描中出现这些路径时单独标明范围，避免将语法建议当作已证实的产品问题。

## 适配边界

- 基础控件继续复用 `@cqu-moe/ui`，先检查组件的公开 API 和实际行为，再判断业务层是否缺失语义或键盘支持。平台指南不构成替换设计系统或覆盖 `.ds-*` 的理由。
- 核对 TypeScript 的 `target` / `lib`、打包目标和实际浏览器要求；类型库升级不等于运行时支持。没有更具体的浏览器策略时，采用技能的 Baseline 默认规则及对应回退。
- 已有取消请求、错误反馈、首帧主题初始化、PDF 按需加载和分页渲染应在实际调用链中核实；不要另建一套同功能机制。
- 私有通知、附件和快照仍实时鉴权。性能建议须保留隐私、安全与数据完整性约束；不能直接将公共页面的缓存示例用于受保护内容。

## 完成条件

报告区分已确认问题、待测性能候选与排除项，附源码位置、用户触发场景和验收办法。改动时检查相关调用者及已有回归，并执行根 `AGENTS.md` 的检查；UI 实际验收与本地构建分开记录。

保持指导为开发时工具，不作为产品运行依赖，也不将会联网变化的 `@latest` 扫描直接设为发布门禁。已确认且可机械判断的缺口优先补入现有检查；有意保留的兼容写法记录理由，不以扫描清零为目标。
