## 已确定的生产约束

1. 首轮仅启用教务处来源，其他原有来源和存档保留；真实验收账号为用户指定的现有账号，使用生产 Auth 稳定 ID。仅对该账号合并 Feed 权益，不改变注册默认预设。
2. 用户授权正式月费用上限人民币100元；隔离验收50元单独核算。初始调用硬限额为 Firecrawl 6次/UTC日、图像OCR 2次/UTC日、PDF OCR 2源页/UTC日且30源页/UTC月；无套餐购买/充值授权。应用调用限额不等于供应商或整个 Cloudflare 账号的人民币账单硬封顶，需结合实际增量账单监控，接近上限暂停付费动作。
3. 正式邮件使用新配置的 Resend Sending access Key，仅限 `feed.cqu.moe`。签名回执负责状态更新；异常在 Resend 后台人工核对，不使用生产 Key 做主动 GET 查询。隔离临时 Full access Key 仅用于管理配置及原隔离验收，完成后提醒撤销，不注入生产。
4. 生产恢复采用 Cloudflare D1 Time Travel 和不可变 R2 保留；原地迁移复用现有OCR，不导出学生名单、不重新OCR凑齐历史验收。恢复点和部署ID保存在受保护的本地发布回执目录。

## 回滚

优先暂停产生新事实的动作：关闭CRAWL、TASK_RUNTIME和MAIL，停Cron并暂停来源；已有邮件webhook仍接收签名供应商事实。`submission_unknown`只能对账，不手动改为未发送或重发。

读取出现回归时关闭ARCHIVE_READS回到旧版存档；T17已验证这条路径。保留所有新旧版本、对象引用、订阅配置、事件、投递账本和受理收据。切换读取与Worker代码不回滚D1/R2内容。

如必须恢复数据库备份，先隔离所有写入并保留当前投递账本/供应商事实，单独审查恢复与合并方案；不能将数据库时间倒退当作普通应用回滚，否则已受理邮件可能重复发送。

扩灰度前的硬门槛：历史原件丢失0、误发历史邮件0、重复邮件0、访问权益绕过0、所有邮件结果不明均有明确处理人和对账记录。性能与费用阈值随生产预算另行确认；本次合成样本不能给出可信的大规模SLO。
