# #70 整点站点错峰：本地验收

范围：`feat/feed-63-70`；初始基线为集成分支的 `1c58b0706e0ce27c1c239747edf1cbaf76ffb121`。未执行生产操作、GitHub 操作或真实源站访问。

## 行为

- 唯一自动扫描入口是整点 Cron，选择条件使用 `controller.scheduledTime` 的 UTC 整点；管理员显式调度保持立即执行。
- 同站 ID 与整点的 SHA-256 前 32 位取模 3600，生成秒偏移。同站分批扫描共用计划，每栏独立去重；下一小时重算。
- 最早开工时间写入 `tasks.due_at`，同时在现有 payload 的 `scheduledStartAt` 保存不可变原值供来源健康读取。Workflow 重试/退避改写 `due_at` 不延长本轮宽限。启动 outbox 立即可派发，现有统一发送入口负责 Queue 原生延迟。后续页面和其他任务不添加错峰。
- 来源 API 和监控共用有效排班查询。只有本轮到期、当前配置、首轮首次尝试且任务/启动 outbox 无错误的排班改变本轮截止时间；旧漏检及失效计划不延长宽限。
- 页面显示等待计划、处理中和超期，并保留真实成功时间。有效排班使用最早开工后十分钟的处理宽限；无有效排班沿用原七十分钟阈值。
- 无新表、迁移或依赖。排班元数据仅随已有任务 payload 保存。
